# Stage 06 — Independently verify descriptive statistics and t-tests

## Why this stage exists

This is the first stage that proves recorded numbers follow from recorded data using a separate calculation route. It covers the most common building blocks behind scientific annotations: counts, means, variances, standard errors, confidence intervals and independent or paired t-tests. Later statistical stages reuse its comparison, tolerance and reporting machinery.

## Scope

- Implement reference descriptive statistics from canonical table values.
- Verify sample counts, missing counts, means, sample variances, standard deviations, standard errors and requested confidence intervals.
- Implement one-sample, paired, equal-variance independent and Welch independent-samples t-tests.
- Calculate and report intermediate values before final probability values.
- Handle one-sided and two-sided alternatives explicitly.
- Compare numerical fields with per-field absolute and relative tolerances.
- Verify the exact stored probability value and independently generate its display string.
- Record verifier implementation identity and version.
- Refuse `statistics_independently_verified` when the producer and verifier use the same unqualified calculation path.
- Add statistical dependencies under the aggregate `[proof]` extra without making them core import requirements.
- Write independent-check outcomes against the existing publication `test_id` so workbook statistics rows can display status without duplication.

## Out of scope

- Rank tests, analysis of variance and multiplicity belong to Stage 07.
- Regression and resampling belong to Stage 08.
- Scientific test-choice review remains out of scope.
- Visual placement of a correct label belongs to Stages 09–12.

## Implementation sketch

```python
@dataclass
class CalculatedStatistic:
    statistic_id: str
    algorithm: str
    intermediates: dict[str, Any]
    outputs: dict[str, Any]
    backend: dict[str, str]

def calculate(spec: StatisticalSpec, table: CanonicalTable) -> CalculatedStatistic: ...
def compare_statistic(spec: StatisticalSpec, actual: CalculatedStatistic) -> list[VerificationCheck]: ...
```

For `welch-t/v1`, calculate directly from the canonical group values:

```text
t = (mean1 - mean2) / sqrt(variance1/n1 + variance2/n2)

df = (variance1/n1 + variance2/n2)^2
     / ((variance1/n1)^2/(n1-1) + (variance2/n2)^2/(n2-1))
```

Use a maintained special-function implementation for distribution tails, but keep the means, variances, statistic and degrees-of-freedom formula in ReproFig’s reference route. Record that backend so a producer using the same dependency can be labelled `statistics_reproduced` rather than silently assumed independent. Validate against fixed values generated by at least one separate language/runtime and preserve those fixtures.

Comparison report example:

```text
comparison-01.n                 pass
comparison-01.means             pass
comparison-01.variances         pass
comparison-01.statistic         pass
comparison-01.df                pass
comparison-01.p_exact           pass within declared tolerance
comparison-01.display_text      pass exact string
```

## Exit gate

1. Reference fixtures cover ordinary, unequal-size, unequal-variance, paired, one-sided and missing-value cases.
2. Every t-test exposes counts, means, variances, test statistic, degrees of freedom and probability value.
3. Deliberately changing one source value identifies the first mismatching intermediate.
4. Exact stored values compare numerically; displayed values compare through the recorded formatter.
5. A producer/verifier independence policy is recorded and tested rather than inferred from matching answers.
6. Importing base `reprofig` works without the statistical extra.
7. `pytest tests/test_statistics_common.py -q` passes against every supported Python version.
8. Building and extracting figures or workbooks without the statistical extra remains unchanged; independent checks run only when requested.

## Known risks

- Floating-point equality is not portable. Tolerances must be strict, field-specific and visible in the report.
- Using the same library twice is reproduction, not strong independence. Record implementation identity and downgrade honestly.
- Distribution-tail behavior for extreme values can differ. Include extreme and degenerate fixtures and never silently clamp a result.
